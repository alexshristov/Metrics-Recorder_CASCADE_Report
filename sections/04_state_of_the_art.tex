\section{State of the Art and Related Work}
\label{sec:state-of-the-art}



\subsection{Detecting Inconsistencies}

Testing source code and its documentation on its consistency has long been an important topic in software engineering.
The recent advances of LLMs has created the possibility for a number of new approaches. 
One of these approaches is DocChecker \cite{DocChecker}. 
It uses a pre-trained language model to identify and correct inconsistent comments.
Another related approach is C4RLLaMA \cite{C4RLLAMA}, which also compares comments with code with its fine-tuned model based on the open source model CodeLLaMa.
These approaches prior to CASCADE \cite{Kiecker_2026} demonstrate, that LLM's can outperform traditional aproaches without them.

\subsection{LLM Efficiency Detection}


One tool, which is a bit outside of the topic, but still uses LLM's and has an efficiency analysis is FD-FACTORY \cite{FD-FACTORY}.
In this tool LLM's are used to generate fuzz driver for DL API testing.
It aims to analyse reliability and security. The efficiency analysis includes API Call, tokens and repair cycles.
This is very similar to the aproach we will do on the CASCADE paper.
Efficiency analysis on LLM tools is already done in many papers, but we noticed that in papers about inconsistency detection it is missing most of the time and think that it would add to the quality of research in this field.
